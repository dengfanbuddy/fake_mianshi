# ADR-0003: 语音交互方案 — 录音后发送 + 腾讯云 STT/TTS

**Date:** 2026-08-01
**Status:** Accepted

## 背景

模拟面试需要语音输入（用户说话）和语音输出（面试官播报），并基于语音分析回答的流畅度和语气。需要选择交互模式和语音服务。

## 决策

- **交互模式**：MVP 阶段采用录音后发送模式，后续迭代支持实时流式对话
- **STT/TTS 服务**：腾讯云 ASR（语音识别）+ TTS（语音合成）
- **音频保存**：用户录音保存到文件系统，数据库存路径引用
- **分析方式**：流畅度基于 STT 文本推断，语气/情绪 MVP 阶段基于文本由 LLM 推断

## 考虑的方案

### 交互模式

#### 录音后发送（已选）
按住录音 → 停止 → 发送至后端 → STT 转文字 → LLM 处理 → TTS 播报回复。

- 优势：技术复杂度低，可靠，开发快
- 劣势：对话感不如实时流式，有等待间隙

#### 实时流式（豆包模式）
WebSocket + 流式 STT + 流式 TTS，边说边转、边生成边播。

- 优势：最接近真实对话体验
- 劣势：技术复杂度高（WebSocket + 流式音频 + 流式 LLM），调试困难

### 语音服务

#### 腾讯云（已选）
ASR + TTS 服务，中文识别/合成质量好，与国内网络延迟低。

#### 浏览器内置 API
Web Speech API，免费零成本，但中文 STT 质量不稳定，TTS 音色机械感强，且浏览器兼容性差。

#### 其他云服务
阿里云、Azure 等，质量也不错但用户倾向腾讯云生态。

## 理由

1. MVP 优先验证核心体验（AI 出题 + 语音面试 + 分析报告），录音后发送模式足以支撑。
2. 腾讯云中文语音质量优于浏览器内置 API，且后端代理调用无 CORS 问题。
3. 保存录音用于回放复盘，文件系统存储避免 SQLite 存大文件的性能问题。
4. 语气/情绪分析基于文本推断虽不够精准，但 MVP 阶段可接受，后续可扩展音频信号分析。

## 后果

- 录音后发送模式有等待间隙（STT + LLM + TTS 各需数秒），用户体验不如实时流式。需在 UI 上做 loading 动画缓解。
- 腾讯云语音服务需要配置 API Key，产生调用费用。
- 后续迁移到实时流式需要重构前后端通信（从 HTTP 请求/响应改为 WebSocket）。
