# ADR-0002: 自适应出题采用混合模式

**Date:** 2026-08-01
**Status:** Accepted

## 背景

系统需要根据历史面试表现智能生成新题——优先覆盖常错知识点、深挖简历项目。需要决定自适应出题的实现机制。

## 决策

采用**混合模式**：系统从历史面试分析中提取结构化弱点标签 + LLM 基于标签生成题目。

## 考虑的方案

### 方案 A：结构化知识图谱（未选）
系统维护一张 Java 知识点图谱（如 JVM → GC → G1 算法），每次面试后标记掌握/未掌握状态，出题时按图谱选择未覆盖节点。

- 优势：精准可控，可追踪知识覆盖度
- 劣势：需要设计和维护知识图谱，工作量大；图图谱覆盖面有限，难以涵盖所有技术点

### 方案 B：LLM 全上下文驱动（未选）
把历史面试记录和分析全文塞进 prompt，让 LLM 自行决定出什么题。

- 优势：零维护成本，灵活
- 劣势：token 消耗大；LLM 对长上下文的利用不可控，可能遗漏关键弱点

### 方案 C：混合模式（已选）
从历史分析中提取弱点标签（如 "JVM调优-弱""并发编程-弱""Redis-已掌握"），LLM 出题时接收标签 + 简历 + 职位需求。

- 优势：无需完整知识图谱，但比纯 LLM 更可控；标签可持久化，跨次面试积累
- 劣势：标签提取依赖 LLM 分析质量，标签粒度需调优

## 理由

1. 结构化知识图谱维护成本过高，且 Java 技术栈广度难以穷举。
2. 纯 LLM 上下文驱动不够精准，且随着历史增长 token 消耗线性增加。
3. 混合模式在精准度和维护成本间取得平衡：弱点标签是轻量级结构化数据，提取和更新由 LLM 完成，存储和查询成本低。

## 后果

- 需要设计弱点标签的数据结构（知识点 + 掌握程度 + 出现次数 + 最后面试时间）。
- 标签质量依赖 LLM 分析的 prompt 设计，需要迭代调优。
- 未来如需更精准的知识追踪，可逐步向知识图谱演进。
