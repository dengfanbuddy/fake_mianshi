# ADR-0011: 弱点标签按归一化主题归并，并在启动时改写存量数据

## 状态

已采纳（2026-10-20）

## 背景

`weakness_tag.knowledge_point` 是分析用的 LLM **每轮现起**的自由文本。项目 1 跑了十几轮面试后，
库里积了 69 条标签，实测其中：

- 12 条是同一个知识点 LongAdder（`LongAdder底层原理` / `LongAdder.sum()弱一致性` /
  `JUC并发工具（LongAdder vs AtomicLong）` …）
- 18 条是同一个知识点 Redis 分布式锁（`Redisson看门狗机制` / `Redis单线程模型与Lua原子性` …）
- 10 条是同一个知识点 CPU 飙高排查

这不只是「错题本左栏很吵」的观感问题，它造成三个功能性错误：

1. `resolveMasteryLevel(count)` 只在 `occurrence_count ≥ 2` 判 WEAK。写法一分散，
   每条都只出现 1 次，**顽固弱点永远判不出来**。
2. 错题订正后的掌握度回写用 `point.equals(tag.getKnowledgePoint())` **精确匹配**。
   题目上的知识点和标签名对不上，回写静默失效——用户订正了，掌握度一动不动。
3. 按知识点筛错题用子串包含。归并后代表写法与题目里的原始写法不一致，
   点一下知识点可能一条错题都筛不出来。

## 决策

### 1. 停止精确匹配，改为「归一化主题」

新增 `KnowledgePointNormalizer`（确定性、不调 LLM、可在单测里回归）：

- 归一：NFKC → 只留字母数字汉字 → 小写 → 反复删多字噪声词
- 相似：字符 bigram 的 Dice 系数
- 判定：归一后相等 / 一方包含另一方 / Dice ≥ 0.45

阈值 0.45 是**在真实数据上量出来的**，不是拍脑袋：0.55 → 33 个主题（漏合并），0.50 → 27，
0.45 → 23，0.40 → 18 且开始把「死锁检测」并进整片死锁内容。回归样本固化进
`backend/src/test/resources/weakness-tags.sample.txt`，`KnowledgePointNormalizerTest`
锁住簇数与几个具体的「必须合并 / 绝不能合并」的用例。

刻意**不删单字连词**（与 / 及 / 和 / 的）：中文里它们与构词成分无法区分，
删掉「线程亲和性」里的「和」会得到「线程亲性」，反而离「线程池哈希分发」更远。

刻意用 Dice 而不是最长公共子串：`redis单线程模型…` 与 `redisson看门狗…` 的最长公共子串是
`redis`（比值 0.56，在阈值附近会误合并），Dice 只有 0.36（正确分开）。

### 2. 三层一起修，缺一层都不成立

| 层 | 做法 | 单独做会怎样 |
|---|---|---|
| 源头 | 分析 prompt 附上项目已有知识点清单，要求同一知识点照抄旧名字 | 只做这层，存量数据依旧是脏的 |
| 写入 | `recordOccurrence` 按归一化键匹配，命中就累加并记别名 | 只做这层，69 条永远是 69 条 |
| 存量 | 启动时归并一次（幂等） | 只做这层，下轮分析又开始造新写法 |

实测：改完后对同一项目跑一次全新分析，LLM 产出的 5 个知识点**全部**落到了已有标签上
（其中 2 个是照抄的标签代表名），标签总数 23 条不变、零新增；而改前同样的分析会新增 5 行。

### 3. 在启动时改写存量数据（这是本 ADR 最需要辩护的一条）

`WeaknessTagConsolidator` 在 `CommandLineRunner` 里对每个项目跑一次归并。

**为什么不在后台等用户手点**：留下一个「一键归并」按钮，绝大多数用户不会点；
而这一页恰恰是「看起来坏掉了」的那种坏——用户看到 69 条重复项，不会去猜有个按钮能修。

**为什么这样做是安全的**：

- 幂等：没有可合并的簇就什么都不做（第二次跑 `merged = 0`）
- **不丢信息**：被合并掉的写法全部留在 `aliases` 里，界面上以「N 种说法」展示，可悬停查看
- 失败不阻塞启动：每个项目单独 try/catch，异常只 warn
- 可回滚：把 `aliases` 拆回行即可，没有不可逆的结构变更

### 4. 掌握程度取簇内最差，不从次数重推

合并后 `occurrence_count` 会变大，若顺手用 `resolveMasteryLevel(count)` 重算，
「已订正成 GOOD」的行会被次数一冲退回 WEAK——等于把用户的复习成果抹掉。
因此归并时掌握程度取簇内**最差**（`WEAK > FAIR > GOOD`），只做「保守降级、绝不升级」。

### 5. 簇代表名用 medoid，不用最高频

82% 的情况下「出现次数最多」的那个名字最具体（`Redisson看门狗与leaseTime`），
拿它当整簇标题会误导。改用「到簇内其它成员平均相似度最高」的写法，
实测选出来的是 `Redisson分布式锁Lua脚本与原子性` / `LongAdder底层原理` 这类更中性的名字。

## 后果

- 项目 1：69 → 23 条标签，46 条同义写法进 aliases；项目 2：4 → 3 条
- `occurrence_count` 开始有意义：LongAdder 累计 17 次、Redisson 30 次、排查 14 次，顽固弱点终于判得出来
- 错题本左栏可点击的条目从 69 降到 23，且默认只显示前 8 条（按薄弱程度 + 次数排序）
- 「订正 → 掌握度上调」恢复工作（`improveMastery` 改用 `findSameTopic`）
- 按知识点筛错题改为按 `tagId` 筛，后端带上全部同义写法匹配；标签已不存在时**明确筛空**，
  而不是悄悄忽略筛选条件把全部错题端出来
- 每次分析会多花约 60 行 prompt 放已有知识点清单（`EXISTING_POINTS_LIMIT`，超出截断）

## 已知局限

- 22% 的簇是「只能靠 Dice 阈值勉强连上」的：`线上故障排查方法论` 与
  `JVM线程状态与CPU消耗关系` 被并进同一簇。这是单链接聚类的固有代价，接受。
- 归并后簇内成员跨度可能较大（Redis 那一簇 18 种写法涵盖单线程模型、Lua 原子性、看门狗续期）。
  用户仍可从别名列表里看到细分写法，但**不能**再按细分写法单独筛选。
  真要做成两级分类（主题 / 细分），需要让 LLM 参与命名，属于另一个量级的改动。
- 归一化是中文 + 英文标识符启发式，换成纯英文知识点名的项目效果会退化（无分词，bigram 对英文短语偏松）。
