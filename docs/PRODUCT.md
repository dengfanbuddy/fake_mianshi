## 1. 产品概述

### 1.1 产品定位

**AI 面试模拟系统**是一款面向求职者的**全流程面试训练工具**：上传简历 → AI 自动出题 → 笔试 + 语音模拟面试 → 多维度分析报告 → 基于历史自适应查漏补缺，形成「练-考-评-补」的完整闭环。

### 1.2 目标用户

- **求职者**：即将面试、需要系统化训练的人群（应届生、跳槽者、转行者）
- **培训者**：可指导学员进行结构化面试演练

### 1.3 核心价值

| 价值点 | 说明 |
|---|---|
| 全流程模拟 | 笔试 + 语音模拟面试，真实还原面试节奏 |
| 自适应出题 | 基于历史弱点标签 + LLM 动态出题，越练越精准 |
| 多维度分析 | 单题分析 → 单次会话分析 → 历史综合分析，三层递进 |
| 任意职业支持 | 提示词按职业分类，AI 自动为每种职业生成专属面试指令 |
| 零门槛部署 | 单机 SQLite + 页面化配置，打包分发后无需环境变量 |

### 1.4 分支说明

| 分支 | 定位 |
|---|---|
| `main` | Java 后端方向（初始版本，面试提示词面向 Java 岗） |
| `generic-interview` | **通用面试版（当前）**：任意职业，提示词按职业分类可配置 |

## 3. 核心功能详解

### 3.1 项目管理

- 项目 = 一次求职准备主题（按目标岗位分组管理）
- 创建/编辑时可填写**目标岗位**（如"Java后端开发""产品经理""前端工程师"），系统据此匹配对应职业的面试提示词
- 项目列表直接展示目标岗位标签
- 项目下关联：简历、职位需求、笔试会话、面试会话、分析报告

### 3.2 简历上传与解析

- 支持 PDF 格式上传
- AI 解析产出：候选人信息、技能清单、项目经历、教育背景、**建议应聘岗位**
- 解析结果可一键生成职位需求

### 3.3 笔试模块（Written Test）

- **AI 出题**：基于职位需求 + 简历 + 历史弱点标签，动态生成
- **题型**：单选（50%）/ 多选（15%）/ 填空（10%）/ 简答（25%）
- **题量/时限**：默认 12 题、60 分钟（开始前可调整）
- **判分**：客观题自动判分；简答题 AI 辅助判分
- **恢复**：离开/刷新后，通过项目页"继续笔试"入口恢复进行中的考试
- **出题过程**：SSE 流式实时展示 AI 生成过程

### 3.4 模拟面试模块（Mock Interview）

- **AI 面试官**：根据职位需求 + 简历 + 弱点标签 + 面试大纲，动态追问
- **语音交互**：候选人录音 → 腾讯云 STT 识别 → AI 回复 → 腾讯云 TTS 合成语音播放
- **面试官风格**：
  - 预设：技术深挖型 / 压力面试型 / 温和引导型 / 项目实战型 / 八股文型
  - 自定义：任意创建（名称 + 描述，影响 TTS 音色与话术）
  - 开始前选择：手动 / 随机 / 智能推荐
  - 面试中可切换（AI 检测到匹配度低会主动建议换人）
- **面试大纲**：AI 根据职位/简历/弱点生成考察重点（技术/项目/行为）
- **历史恢复**：刷新后通过 `?sessionId=` 恢复完整对话继续面试

### 3.5 分析报告体系

**三层递进分析**：

```
第一层：单题分析（question_analysis）
  每道题：类别 / 难度 / 考察点 / 准确度/深度/清晰度/流畅度 打分 + 依据
         回答思路 / 优秀示例 / 改进建议

第二层：单次会话分析（session_analysis）
  总体评分 0-100 / 能力等级 / 预期薪资区间
  优势 / 弱点清单 / 知识盲区（含答案要点）
  性格画像（特质/缺陷）/ 沟通评价（面试）
  改进计划（方向+做法+实例）/ 幽默总结

第三层：历史综合分析（historical_analysis）
  维度趋势（上升/平稳/下降）/ 反复出现的弱点
  下次重点练习方向 / 整体成长评价 / 幽默总结
```

**分析触发**：
- 笔试提交后 / 面试结束后自动生成（或手动"重新生成分析"）
- 历史综合分析：手动进入生成；检测到新分析结果时提示可"重新综合分析"

**幽默总结（面试官大实话）**：AI 根据得分给出趣味化总结——高分谄媚捧脚（"大佬，收徒吗？"）、低分善意吐槽（"菜的扣脚，回家种红薯去吧"）、中等鼓励，展示在报告顶部。

### 3.6 弱点标签（自适应出题核心）

- 每次分析后自动提取弱项知识点，写入项目的弱点标签库
- 下次笔试出题/面试大纲优先覆盖这些弱点
- 弱点标签随时间沉淀，形成个人查漏补缺地图

## 4. 使用流程（快速上手）

### 第一步：创建项目

1. 打开系统 → 「项目管理」→ 新建项目
2. 填写项目名称 + **目标岗位**（如"前端开发工程师"）
3. 保存后系统自动匹配（或为新职业自动生成）面试提示词

### 第二步：完善面试背景

1. 进入项目 → 上传 PDF 简历 → AI 解析
2. 生成职位需求（可手动调整）

### 第三步：开始训练

- **完整流程**：笔试 → 模拟面试 一站式
- **分开训练**：只做笔试 / 只做模拟面试

### 第四步：查看分析

1. 笔试提交 / 面试结束后，生成分析报告
2. 查看单题点评、整体评估、知识盲区、幽默总结
3. 多次训练后查看「历史综合分析」掌握成长趋势

### 第五步：查漏补缺

- 每次分析产出的弱点标签自动用于下一次出题
- 可在「提示词管理」中针对职业微调 AI 指令，让题目更贴合目标岗位

## 5. 技术架构

### 5.1 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | Vue 3 + Element Plus + Pinia + Vite | SPA，中文界面 |
| 后端 | Spring Boot 4.1 + MyBatis-Plus | Java 17+ |
| 数据库 | SQLite（WAL 模式） | 免安装单文件，自动建表/迁移 |
| LLM | DeepSeek API（OpenAI 兼容，可在设置页切换） | 出题/面试/分析/提示词生成 |
| 语音 | 腾讯云 ASR（一句话识别）+ TTS（语音合成） | 语音面试交互 |
| 通信 | SSE（Server-Sent Events） | 出题/分析流式输出 |
| 简历 | PDF 解析 | 上传解析为文本 |

### 5.2 系统架构

```
┌────────────────────────────┐
│       前端（Vue3 SPA）       │
│  项目管理/笔试/面试/分析/设置  │
└────────────┬───────────────┘
             │ REST API + SSE
┌────────────▼───────────────┐
│     后端（Spring Boot）      │
│  Controller → Service → DAO │
│  · 笔试/面试/分析/提示词服务   │
│  · SSE 流式（SseEmitter）    │
│  · 异步任务（分析/提示词生成） │
└─────┬────────────┬─────────┘
      │            │
┌─────▼─────┐ ┌────▼──────────┐
│ SQLite    │ │ 外部服务        │
│ 17 张表   │ │ DeepSeek LLM   │
│ (WAL)     │ │ 腾讯云 ASR/TTS │
└───────────┘ └───────────────┘
```

### 5.3 关键设计

- **SSE 流式**：AI 出题、分析报告生成全程流式推送，前端实时展示；8 秒无输出自动切换轮询兜底，保证反馈
- **配置实时生效**：AI 模型、语音密钥存数据库，保存即激活，调用时实时读取（无需重启）
- **超时与并发**：LLM 请求 300 秒超时；SQLite 采用 WAL + busy_timeout + 短事务 + 单线程生成任务，避免写锁冲突
- **长任务容错**：LLM 输出代码块围栏自动剥离；JSON 解析容错（提取 `{}` 主体）
- **数据库迁移**：启动时检测缺失列自动 `ALTER TABLE` 补齐（旧库无缝升级）

## 6. 数据模型

核心表（共 17 张）：

| 表 | 用途 | 关键字段 |
|---|---|---|
| `interview_project` | 面试项目 | name、**target_position**（目标岗位）、description |
| `interview_session` | 面试会话 | project_id、type（WRITTEN/MOCK）、status（IN_PROGRESS/COMPLETED）、time_limit |
| `interviewer_persona` | 面试官风格 | name、description（影响 TTS 音色） |
| `written_test_question` | 笔试题 | session_id、type、content、options、answer、explanation、knowledge_points |
| `written_test_answer` | 笔试作答 | session_id、question_id、answer、auto_score、ai_score |
| `mock_interview_message` | 面试对话 | session_id、role（INTERVIEWER/CANDIDATE）、content、audio_path、persona_id |
| `resume` | 简历 | project_id、file_path、parsed_json |
| `position_requirement` | 职位需求 | project_id、job_title、experience、tech_stack、job_description |
| `session_analysis` | 会话分析 | session_id、overall_score、overall_level、strengths、weaknesses、knowledge_gaps、improvement_plan、**humor_summary** |
| `question_analysis` | 单题分析 | session_id、question_id、accuracy/depth/clarity/fluency、answer_approach、example |
| `historical_analysis` | 历史综合分析 | project_id、analysis_data（JSON）、generated_at |
| `weakness_tag` | 弱点标签 | project_id、tag、count（自适应出题依据） |
| `prompt_template` | 提示词模板 | **occupation**（职业）× **scene**（场景）、content |
| `ai_model_config` | AI 模型配置 | provider、api_url、api_key、model_name、is_active |
| `voice_config` | 腾讯云语音配置 | secret_id、secret_key、app_id、is_active |

## 7. 部署与配置

### 7.1 环境要求

- JDK 17+
- Node.js 18+（前端构建）
- 无需数据库安装（内置 SQLite）

### 7.2 开发环境启动

```bash
# 后端（8080 端口）
cd backend && ./mvnw spring-boot:run

# 前端（5173 端口，代理 /api → 8080）
cd frontend && npm install && npm run dev
```

### 7.3 生产打包

```bash
# 后端打包
cd backend && ./mvnw package -DskipTests

# 前端构建
cd frontend && npm run build   # 产物在 dist/
```

### 7.4 页面化配置（打包分发后免环境变量）

| 配置项 | 位置 | 说明 |
|---|---|---|
| AI 模型（LLM） | 设置 → AI 模型配置 | 任意 OpenAI 兼容 API，填地址/密钥/模型名，保存即激活 |
| 腾讯云语音 | 设置 → 腾讯云语音配置 | SecretId/SecretKey/AppId，保存即激活 |
| 面试官风格 | 设置 → 面试官风格管理 | 预设 5 种 + 自定义 |
| 职业提示词 | 提示词管理 | 按职业×场景查看/编辑/AI 优化 |

> 兼容环境变量：未在页面配置时，LLM 与语音仍可回退环境变量方式（`DEEPSEEK_API_KEY`、`TENCENT_SECRET_ID` 等）。

### 7.5 打包分发注意事项

- 运行时数据在 `backend/data/fake_mianshi.db`（首次启动自动建表+迁移，勿打进安装包）
- 上传目录 `backend/uploads/`（简历/录音）
- 分发给他人后：只需在设置页配置 AI 模型 + 语音密钥即可完整使用

## 8. 提示词体系

### 8.1 按职业 × 场景分类

系统在调用 AI 出题/面试/分析时，会按项目的**目标岗位**查找对应职业的提示词模板；找不到则回退 `default` 通用模板。

| 场景 | 用途 |
|---|---|
| WRITTEN_QUESTION | 笔试出题指令 |
| MOCK_OUTLINE | 模拟面试大纲指令 |
| WRITTEN_ANALYSIS | 笔试分析报告指令 |
| MOCK_ANALYSIS | 面试分析报告指令 |
| HISTORY_ANALYSIS | 历史综合分析指令 |

### 8.2 新职业自动生成

- 创建项目填写新职业 → 后台自动检测该职业是否已有模板
- 缺失 → AI 基于通用模板自动改写为该职业专属（5 场景全部生成）
- 生成校验：输出必须是"指令文本"（以"你是…"开头），若输出 JSON 数据则自动重试，杜绝垃圾内容

### 8.3 管理页能力（📝 提示词管理）

- **查看**：每个场景标明用途，内容完整展示（模板中的 `{position}` 使用时会替换为目标岗位）
- **编辑**：直接修改并保存
- **AI 优化**：一键让 AI 针对该职业重新生成（可反复优化）
- **补齐**：手动触发为新职业补齐缺失场景

## 9. 常见问题与故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面显示"正在连接 AI"很久 | LLM 未配置或密钥错误 | 设置页检查 AI 模型配置 |
| 分析生成失败（JSON 解析） | LLM 输出异常 | 点"重新生成分析"重试 |
| 语音不可用 | 腾讯云密钥未配置 | 设置页配置语音密钥 |
| 数据库锁定（SQLITE_BUSY） | 长时间 AI 任务占用 | 已优化：提示词生成不占长事务；重启后端可恢复 |
| 切分支后报"no such column" | 旧库缺列 | 自动迁移已处理（启动时自动加列） |
| 前端不更新 | 浏览器缓存旧 JS | Ctrl+Shift+R 强刷 |

## 10. 已知限制与后续规划

### 已知限制

- SQLite 单机架构，适合个人/小团队使用，不支持多用户并发部署
- 语音交互为"录音后发送"模式（非实时流式）
- 简答题依赖 AI 判分，极端情况下可能不稳定
- 历史综合分析的维度趋势需要多次面试数据积累

### 后续规划（建议）

- [ ] 实时流式语音对话（WebSocket）
- [ ] 多用户账号体系（数据隔离）
- [ ] 简历对比分析与岗位匹配度报告
- [ ] 面试报告导出（PDF/Markdown）
- [ ] 更多音色/多语言面试支持
- [ ] 提示词市场（职业模板社区共享）
- [ ] Docker 一键部署
